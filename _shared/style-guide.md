# 執筆スタイルガイド

統合 CV / portfolio / 領域ノートの品質と一貫性を維持するための執筆指針。
業界のベストプラクティス (UBC Technical Writing / Google / Microsoft / O'Reilly) に基づく。

> [!NOTE]
> 本ファイルは career-research-skill のバンドルリソース (汎用版)。 本人プロジェクト内で specialized なスタイル指針がある場合は、 `research/_shared/style-guide.md` で上書きすると個別 PJ に最適化できる。

---

## 1. 散文 (プロース) の長さ

### 1.1 一文の長さ

| 指標 | 推奨値 | 根拠 |
|---|---|---|
| 日本語 | **60 文字以内** | 読点は約 20 文字ごとに打つ |
| 英語 (引用時) | 15–20 語 | gov.uk / Google Style Guide |

> **原則:** 主語は文頭から 6 語 (日本語では 10 文字) 以内に置く。 読者が「誰が何をした」 を即座に把握できるようにする。

### 1.2 段落の長さ

- **4–5 行 (3 文程度)** を基本単位とする
- 1 段落 = 1 メッセージの原則を厳守
- 最大でも **8 行 (150 語相当)** を超えない
- 1 文だけの段落は強調として例外的に使用可 (章に 2–3 回まで)

### 1.3 連続散文の限界

- **半ページ (約 300–400 文字) を超える連続散文は避ける**
- 見出し・表・図・箇条書き・ブロック引用のいずれかで視覚的な休憩を挿入する
- 認知負荷の上限は **4–6 個の新概念** — それを超えたらまとめか休憩を入れる

> **理由:** 技術文書の読者は楽しみのためではなく必要に迫られて読む。 スキャナビリティ (走り読みのしやすさ) を最優先に最適化せよ。
> — *Technical Writing Essentials (UBC)*

## 2. 章の長さと構成

### 2.1 章の長さ

| 指標 | 推奨値 |
|---|---|
| 1 章あたりの文字数 | **10,000–14,000 文字** (A5/B5 換算で約 10 ページ) |
| 章の総数 | 5–7 章 (部をまたぐ場合は部ごとに 3–5 章) |
| 章間のばらつき | **平均値の ±10% 以内** が理想 |

### 2.2 見出し階層

- **最大 3 階層** (`##`, `###`, `####`) まで。 h5 以下は使わない
- 箇条書きのネストも **最大 2 階層** まで
- 目次に載せる見出しは `##` と `###` のみ

### 2.3 章の統一構造テンプレート

```
## 章タイトル

導入文 (1–3 文): この章が扱う中心的な問い

> **この章で学ぶこと:**
> - 学習目標 1
> - 学習目標 2
> - 学習目標 3

### セクション 1 (理論・フレームワーク)
散文 + 表 + 図

### セクション 2 (具体例・事例)
具体例ブロック × 2–4

### セクション 3 (応用・比較)
比較表 + 散文

### この章のまとめ
1–3 文の統合

### さらに学ぶために
- 推薦文献 3–5 件
```

## 3. 図表・視覚要素の頻度

### 3.1 推奨頻度

| 要素 | 推奨頻度 | 根拠 |
|---|---|---|
| 表 (比較表・分類表) | **各セクションに 1 つ以上** | 数値やカテゴリの比較は散文より表が優位 |
| Mermaid 図 | **各章に 1 つ以上** | 関係性・フロー・分類の可視化 |
| ブロック引用 | **2–3 ページごとに 1 つ** | 出典・補足・注意喚起 |
| 箇条書き | **連続散文が 5 行超えたら** 検討 | リスト化で認知負荷を下げる |

### 3.2 目標: ページ面積の 20–30% を視覚要素に

日本語技術書のデータによると、 10 万文字の書籍で実質テキストは 7–8 万文字。 残り **20–30% は視覚要素**が占める。

### 3.3 図表の配置ルール

- 図表は **参照する散文の直後** に配置する (「図 X を参照」 の後、 次の段落の前)
- 1 ページをまたぐ大きな表は付録に移す
- すべての図表にはキャプション (太字テキスト) を付ける
- 装飾目的の図は入れない — すべて内容を補足するものであること

## 4. 文体・トーン

### 4.1 基本方針

- **学術的だが会話的** なトーン (一人称ではなく「ここで考えてみよう」 形式で読者と並走)
- 想定読者を最初に固定 (例: 「想定読者: 業界経験 N 年のエンジニア」)
- 一人称は使わず、 読者と著者が一緒に考える姿勢

### 4.2 用語

- 日本語の概念名 + 英語の括弧書き: 「(例) 仮想キャッシュアドバンテージ (Virtual Cache Advantage)」
- 初出時に定義、 以降は括弧なし
- 製品名 / 著者名は **太字**

### 4.3 具体例の書式

```markdown
**具体例:** **[ドメイン / 製品名]** の **[著者 / 設計者名]** は [出典 / 年] で
「[引用]」 と述べた。
[2–4 文の解説: この例がどう原則を体現するか]
```

- 各原則・概念に **2–4 個の具体例** (異なるドメインから)
- 単一ドメインに偏らないように、 複数事例から均等に引く

### 4.4 引用・出典の書式

```markdown
> **出典:** [タイトル] — [著者名, 年] ([URL])
```

## 5. クイックリファレンス — 数値目標一覧

| 指標 | 目標値 |
|---|---|
| 一文の長さ | 60 文字以内 |
| 段落の長さ | 4–5 行 (最大 8 行) |
| 連続散文の上限 | 半ページ (300–400 文字) |
| 章の長さ | 150–250 行 (md) / 10,000–14,000 文字 |
| 章間のばらつき | 平均の ±10% |
| 見出し階層 | 最大 3 レベル (`##`–`####`) |
| 新概念の連続導入 | 最大 4–6 個 (その後休憩) |
| Mermaid 図 | 各章に最低 1 つ |
| 表 | 各セクションに 1 つ以上 |
| 視覚要素の面積比 | 20–30% |
| 具体例 | 各原則に 2–4 個 (異なる事例から) |

## 6. career-research skill 固有の制約 (LL 由来)

- **forced narrative 禁止** (LL20): 学び欄に「N 年スパンの○○の起点」「軸の系譜」「最古事例」「後年の X で繰り返される」 等の forward-looking 文を書かない
- **早期 PJ は簡略テンプレ** (LL21): 学生期 / アルバイト期 / 入社初年度の PJ は「期間 / 役割 / 利用技術 / 概要 / 当時学んだ新技術 / 技術的制約」 で完結
- **コード / リポベース技術評価** (LL22): 自己申告だけで「すごい / 弱い」 判定しない。 当時学んだ新技術 + 技術的制約 (未習得点) を両方書く
- **開始年順ソート** (LL29): 各セクション内で details / main section を開始年 (asc) で並べる
- **役割境界の明示** (LL30): 「本人主担当 / 単独」 と「他メンバー主担当 + 本人手伝い」 を必ず分けて書く
- **「細いやつ」 は省略** (LL34): 単体で 300 字以上書けないものは portfolio に載せない
- **rubric 適用結果は散文展開** (LL39): リンクだけでなく本文に散文展開
