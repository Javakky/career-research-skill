## 0. 採点方針

### 0.1 採点記号

| 記号 | 意味 |
|---|---|
| ✅ | 完全達成 |
| 🟡 | 部分達成 |
| ⚪ | 観測不可 |
| ❌ | 未達 |
| N/A | 該当外 |

### 0.2 確度ラベル

| ラベル | 意味 |
|---|---|
| 観測事実 | 一次資料 (公式 / 出典明示) で直接確認可 |
| 外部比較 | 他事例との比較 / 公開人口データ等 |
| 推定 | 判定者の解釈を含む |
| 未確認 | 外形観測不可 |

### 0.3 採点単位

「単一 <役割名> の <ドメイン> 活動として」 採点する。 複数役割 / 複数ドメインの並行は個別採点 + § N+1 で統合する。

## N+1. 集計方法

各カテゴリの **完全達成 ✅ = 1 点 / 部分達成 🟡 = 0.5 点 / 未達 ❌ = 0 点 / N/A は分母から除外** で集計。

| カテゴリ | 重み | 備考 |
|---|---:|---|
| 1. <カテゴリ 1> | 0.20 | <重みの根拠> |
| 2. <カテゴリ 2> | 0.20 | |
| 3. <カテゴリ 3> | 0.15 | |
| ... | ... | |

総合スコアは **加重平均** (`Σ (カテゴリ % × 重み) ÷ Σ (重み)`) で計算。

## N+3. 採点の限界

- アナリティクス非公開 / 外形観測不可な項目は採点できない
- 「コミュニティ貢献」 等は別プラットフォーム (X / Discord) との照合が必要
- 商用化 / マネタイズを目指していない場合は該当カテゴリを N/A で処理する判断が重要
- 単一軸専門化と対照的な **マルチアーキタイプ**の評価では複数 rubric の合算が必要

## 使い方

1. このテンプレートを `_shared/rubrics/<cat>/<rubric-name>-rubric.md` にコピー
2. `<rubric-name>` / `<ドメイン>` / `<役割名>` を具体化
3. カテゴリ 1-N を埋める (4-8 項目 × N カテゴリ / 重みの合計が 1.0)
4. 本人 PJ への適用は `_rubric-applied-examples/<cat>/<rubric-name>-applied-<userid>.md` で別ファイル
5. 適用ファイルでは項目別 ✅/🟡/⚪/❌ + 確度ラベル + 実数値 + 一次資料パス を埋める (Layer 3 / Phase 5)
