# 月別プロジェクト割当て表 (ドラフト)

<開始年> から本基準日 (`<yyyy-mm-dd>`) まで、 月ごとに「最も価値のある経験」 1 件を選定する。 本業に偏らず、 個人 OSS / 副業 / コミュニティ / 発信を横断して選ぶ。 値のない月はスキップする。

## 出典タグ凡例

skill が自動的に決定。 代表例:

- **Q**: Qiita / **Z**: Zenn / **N**: note / **P**: <主たる業務ブログ>
- **GH**: GitHub (公開リポ / 上流 OSS)
- **GL**: 内部 GitLab (業務リポ)
- **G**: 月次面談 / 社内 Notion / 1on1 ログ
- **MCP-Discord**: Discord MCP 経由 / **MCP-Slack**: Slack MCP 経由 / **MCP-Notion**: Notion MCP 経由
- **YT**: YouTube
- **X**: X (Twitter) ポスト
- **Local**: `assets/` 配下のローカル一次資料
- **Self**: 本人申告 (コード / API から復元不可)

複数経路で確認できた事実は出典をカンマ区切り (例: `GH + Local`)。

## 選定基準 (skill の内部ポリシー)

複数のアウトプットが同月にある場合、 次の優先度で 1 件を選ぶ:

1. **公開実績** (記事 / 登壇 / OSS リリース) — 後から検証可能で永続的
2. **リーダー登用 / 案件着手日** — キャリア構造の節目
3. **集中コミット期** (単月 N コミット以上) — 数値で観測できる
4. **受賞 / 認定** — 外部評価
5. **自発的アウトプット** (個人 OSS / 副業前史 / 創作)

業務の通常コミットは「(該当なし、 スキップ)」 扱いでよい。 **月ごとに 1 件選ぶことよりも、 出典のないファクトを書かない方が重要**。

## 月別件数のサマリ (最後に集計)

| 期間 | 月数 | 該当月 | スキップ月 |
|---|---:|---:|---:|
| YYYY (フェーズ) | 12 | N | M |
| **合計** | **N** | **N** | **N** |

スキップは初期 (フェーズ A) に集中し、 フェーズ B 以降は全月選定可能なはず。
